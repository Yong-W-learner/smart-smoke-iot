# `smoke_db` 数据库表结构说明

> 数据来源：2026-08-31 直接查询当前 MySQL `information_schema`。当前共 26 张表，其中 18 张服务于森林公园业务，8 张为早期小区智慧烟感业务遗留表。

## 一、核心关系

- `forest_equipment` 是统一设备台账，通过 `id` 与 `forest_sensor_node.id`、`forest_drone.id` 等业务设备编号关联。
- `forest_equipment` 与 `forest_equipment_fault`、`forest_equipment_self_test`、`forest_maintenance_record` 是一对多关系。
- `drone_mission` 与 `drone_telemetry`、`drone_mission_photo` 是一对多关系。
- `drone_mission_incident` 连接巡护任务 `drone_mission` 与火情事件 `forest_incident`。
- `forest_sensor_node.camera` 逻辑关联摄像头设备编号；`zone` 逻辑关联 `forest_zone.name`。
- 当前数据库主要通过业务编号进行逻辑关联，尚未声明 MySQL `FOREIGN KEY` 外键约束。

## 四、答辩时建议重点介绍的表

1. `forest_sensor_node`：地面传感器实时监测。
2. `forest_drone` + `drone_telemetry`：无人机状态与连续环境遥测。
3. `forest_incident`：火情发现、核查和结案流程。
4. `drone_mission` + `drone_mission_photo`：护林员无人机巡护闭环。
5. `forest_equipment` + `forest_equipment_fault` + `forest_equipment_self_test` + `forest_maintenance_record`：设备台账、主动自检、自动故障和人工恢复闭环。
6. `forest_zone` + `forest_map`：高德地图、公园边界和自定义分区。
