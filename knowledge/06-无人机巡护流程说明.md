# 无人机巡护流程说明

## 任务生命周期

drone_mission 状态流转：待执行 → 已接收（护林员在移动端抢单/接取）→ 前往现场 →
手动飞行（现场起飞后逐包上传遥测）→ 已完成。日常巡护任务可从"待执行/已接收/前往现场"
直接开始；关联警情的核查任务必须先完成接取与到场。

- POST /api/forest/missions 创建（可携带 incidentId 关联警情，一个警情只允许一个执行中任务）。
- PUT /api/forest/missions/{id}/status 接取（已接收）与到场（前往现场）。
- POST /api/forest/missions/{id}/start 开始手动巡护（仅任务护林员）。
- POST /api/forest/missions/{id}/telemetry 飞行中保存位置、电量、卫星、链路质量与
  PM2.5/温湿度/CO/地表温度等环境读数（写 drone_telemetry，一张表同时存真机与演示数据）。
- POST /api/forest/missions/{id}/photos 上报巡护照片（古树建档、热点复核等分类）。
- POST /api/forest/missions/{id}/complete 返航归档。

## 完成归档与巡护总结

complete 时系统统计遥测（组数、PM2.5/CO 均值与峰值、环境温度与地表温度峰值），
地表温度 ≥ 55℃ 记 1 处热点；随后生成任务总结：

- 配置了可用 OpenAI 兼容接口（Docker 部署默认指向本地 Ollama qwen3:4b）时由模型生成，
  summary_source=llm；
- 接口不可用/超时则使用确定性规则总结，summary_source=rules。火情报警主流程不依赖模型。

归档同时回写无人机为 idle/数据已归档，并把关联警情从 verifying 推进到 processing，
等待护林员在页面人工上报最终处置结果。

## 三级警情自动核查

三级火情会自动创建 EMERGENCY- 前缀任务、指派全体护林员并选择电量最高的空闲无人机；
任一在岗护林员均可开始与上报，不需要抢单。

## 遥测数据表

drone_telemetry 每行包含 mission_id、drone_id、经纬度、altitude、speed、battery、
satellites、link_quality、pm25、temperature、humidity、co、surface_temperature、
wind_estimate、collect_time。AI 助手的 queryDroneMission 工具按任务聚合返回
（sampleCount、最大地表温度/PM2.5/CO/高度），不推送全量原始遥测。
